# Neural Marionette V2 · 鹿角机甲

当前项目下的独立第二版：以 `../neural-marionette` 的当前源码为基础，接入用户在 Tripo 项目中生成、经 Blender 绑骨的鹿角机甲。原版本与外部 `tripo` 项目保留。

## 启动

双击本目录的 **启动数字提线木偶.command**，或：

```sh
npm ci
npm run dev
```

首次下载请先执行 `npm ci`，再运行 `npm run dev`。地址为 **http://127.0.0.1:5179/**；旧版通常使用 5173，外部 Tripo Demo 使用 5178。启动器只复用带有 V2 标记的 5179 页面，不会误打开其他版本。端口被占用时会报错，不自动切换地址，避免手势样本存储位置变化。

## 这版有什么变化

- 默认载入白金鹿角机甲，保留原有六种动作、背景音乐、舞台录像和手势录制功能。
- 「恢复默认机器人」切回原机器人；「载入鹿角机甲」重新加载机甲。也可本地导入兼容的已绑骨 GLB。
- 原有疾跑仍是拇指、小指伸开，中间三指反复摆动。新增每根手指相对自身指根的运动检查，与手掌坐标中的变化交叉确认，避免单个手掌参考点的深度波动被误判成多指运动。
- 已确认的疾跑运动与单指旋转分离；仅有宽泛的疾跑支持手型，不再直接阻止单指转腕判断。
- 正常操控与录制模式互斥。进入录制后暂停主舞台和正常识别，保存后点击「返回正常操控」试用。

界面提示的「手掌朝下」是示范姿势，当前不硬性判定掌心相对地面的方向。普通张手也可能通过外侧手型检查，但必须进一步通过独立手指运动检查才会疾跑。

## 第一次试用

1. 页面载入后先保持摄像头关闭，等待模型状态显示加载完成。
2. 点击「先试播六种动作」，用按钮或键盘 1–6 检查机甲表现。试播里的疾跑会持续循环，直到换动作或返回摄像头操控。
3. 点击「返回摄像头手势控制」，选择「原有手势规则」，再做三指摆动。停止摆动后应收势；可以查看逐指提示或「手掌参考点波动」提示。
4. 需要自定义动作时，再进入录制模式；只录自己想替换的动作。

5179 是新的浏览器存储空间，5173/5178 的个人手势不会自动出现。需要时从旧页面导出 JSON，再在 V2 导入。保持手型模式、个人样本匹配与内置三指规则是不同控制方式，测试内置修复时请选择「原有手势规则」。

## 模型与源码

| 路径 | 用途 |
| --- | --- |
| `public/models/guardian-rigged.glb` | 实际运行的可动机甲，100,754 三角面、15 根骨骼，内嵌贴图 |
| `assets/source/guardian-rigged.blend` | 可继续编辑的 Blender 源文件 |
| `assets/source/tripo-v25-original.glb` | 原始静态模型 |
| `assets/source/manifest.json` | 来源、复制日期及文件 SHA-256 |
| `src/model-import.js` | 本地 GLB 检查、加载和角色切换 |
| `src/model-rig.js` | 将原动作映射到机甲骨架，并补偿脚踝高度 |
| `src/run-gesture.js` | 疾跑的支持手型与两路运动交叉检查 |
| `docs/TECHNICAL_TRAINING.md` | 从原版继承的技术教程；V2 差异以本 README 与 CHANGELOG 为准 |

模型没有内置跑步动画，动作由程序实时驱动。手指没有逐指骨骼，飘带随身体运动；大幅下蹲、转身等动作仍可能出现装甲穿插、接缝或关节拉伸。

## 验证

```sh
npm test
npm run build
python3 tests/v2_browser_test.py
python3 tests/workspace_browser_test.py
python3 tests/gestures_browser_test.py
```

浏览器脚本需要 Python Playwright，默认使用本机的 Chrome for Testing 路径，可通过 `NM_TEST_CHROME` 覆盖 V2 专项脚本的浏览器路径。先启动 5179 服务。

单元测试覆盖模型骨架、蒙皮权重、动作映射、手势识别及掌部参考点噪声。浏览器使用合成手势或关闭摄像头的动作试播，不能代替真人识别率、摄像头延迟或长时间录像验收。相机图片与参考视频不放入新版文档；测试证据默认写入临时目录。
