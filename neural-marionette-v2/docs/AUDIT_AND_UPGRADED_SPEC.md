# 数字提线木偶：审核与提升后的执行规范

版本：1.0 · 2026-09-13

本文件是对用户提供原稿的审核与执行修订，原稿完整保留在上级目录。用户本轮请求是「完整阅读、审核并提高效果标准，之后执行项目」。原稿里要求首轮停止等待确认、指定代理身份等语句是被审核的文档内容，不额外限制本轮已授权的项目实施。

## 审核结论

核心目标成立：一只真人手、21 个点、五条清晰可追溯的线、连续机器人动作。第一版应保留这一因果关系。原稿优点包括屏幕空间连线、滤波与状态机、先用合法替身资产的策略。

需要修订的问题：

| 原稿问题 | 影响 | 本版处理 |
| --- | --- | --- |
| 首选 TouchDesigner，但无许可证、安装与版本证据 | 工程依赖不可复现 | 本机 /Applications 未发现 TD，采用本地 Web 实现并在实施前说明；不生成虚假的 .toe |
| MediaPipe 所谓「置信度」未区分 | 把左右手分类 score 误当跟踪质量 | 检测/存在/追踪阈值分别配置；HUD 明确写左右手分类；不展示虚构关键点置信度 |
| 平滑系数 0.72 未绑定采样率 | 30/60 FPS 下响应不同 | 按实际 dt 和时间常数计算指数平滑 |
| 缺少个人中立姿态与手大小归一化 | 不同用户刚连接就跳动 | 12 个稳定样本平均校准；指尖位置相对腕点、按掌长归一化 |
| 仅定义「无手」，未定义推理停滞 | 最后一帧可能无限保持控制 | 800 ms 数据停滞释放控制；5 秒后显示错误并释放设备 |
| 预览与真人实测边界不清 | 合成输入可能冒充验收 | 模拟状态同时写进 HUD、画布与录制文件名；摄像头异常不自动生成假手 |
| 平均 FPS 掩盖卡顿；推理耗时可能冒充端到端延迟 | 指标失真 | 导出分时间样本、均值、最低窗口 FPS 与推理 P95；端到端另行实拍测量 |
| 「提高效果」缺少比较基准 | 视觉和技术目标无法验收 | 以下量化门槛与证据分级 |
| 「项目是否成功Tape」有残留字符 | 文稿质量问题 | 修订判断标准，删除无意残留 |

## 架构决定与影响

实现：getUserMedia → ImageBitmap → 独立 Web Worker 的 MediaPipe Hand Landmarker → 状态机/校准/滤波 → Three.js Bone 层级机器人 → 关节投影 → Canvas 曲线与视频合成 → 本地录制。

原因：未安装 TouchDesigner；系统 Python 3.9.6 与 Homebrew Python 3.12 动态库故障增加 Python 路径部署风险。Web 运行时已实测可创建 WebGL 和推理 Worker。Blender 已安装，但此版本使用自制机械机器人避免外来模型授权与 Rig 清理阻塞。

影响：交付源码、锁定依赖、本地模型与静态构建，启动时需要本地 HTTP 服务和支持 WebGL2 的桌面浏览器；不交付 TouchDesigner 工程。日后若必须恢复 TD，需要另立移植工作，不把两套工程宣称等价。

## 提升后的效果标准

| 项目 | 工程门槛 | 验证方法 |
| --- | --- | --- |
| 实时输入 | 单手输出 21 个有限 XYZ 点；错误时无假数据 | 真实摄像头、官方图片模型测试、无手输入测试分别记录 |
| 连线端点 | 同一合成坐标，曲线端点数学误差 < 1 像素；人工目标 < 3 px @1080p | 镜像/等比留边/缩放单元测试 + 姿态截图人工复核 |
| 运动 | 头、双臂、胸、Root 连续响应；不使用离散动作切换驱动 | 改变单个指尖与腕点的独立性测试 + 真人测试 |
| 中立校准 | 至少 12 个稳定样本；腕/指尖窗口首尾位移 < 0.035 归一化单位 | 校准状态输出；移动状态不会立即锁定中立 |
| 平滑 | 点滤波时间常数 45 ms；关节 100 ms；dt 自适应 | 30/60/120 Hz 等时响应一致性测试 |
| 限幅 | 关节目标 ≤35°；角速度 ≤2.4 rad/s；位移速度 ≤1.4 世界单位/s | 边界、随机输入与长序列测试 |
| 丢失 | 250 ms 容忍；随后淡出；约 650 ms 回中立的大部分行程 | 状态测试、真人遮挡、恢复校准 |
| 性能 | 桌面 1080p 平均 ≥30 FPS；最低一秒窗口目标 ≥24 FPS | 连续 10 分钟导出诊断；注明真假摄像头、输入有无手 |
| 延迟 | 真人端到端 P95 目标 ≤200 ms；不能拿推理时间替代 | 高速外部相机同时拍真实手和屏幕，至少 20 次变化采样 |
| 录制 | 25 秒本地可播放视频，包含源模式标识 | MediaRecorder、文件探测；真人演示需真人输入 |
| 冷启动 | 已安装依赖和本地模型后，加载界面目标 <10 s，用户允许相机后 <60 s 进入交互 | 全新浏览器会话；权限等待单独计时 |
| 隐私 | 摄像头帧不出本机，默认不启用摄像头/麦克风 | 请求检查、后台自动释放摄像头、本地模型 |
| 可复现 | 锁定依赖版本，启动/配置/架构/故障文档齐备 | npm ci、npm run build、npm test、浏览器回归 |

以上是验收目标，不代表全部已经通过。最终状态只以 progress.md 与证据文件为准。

## 视觉方向

主题：精密互动实验台。左侧手部取景，中间五条琥珀色张力曲线，右侧独立舞台上的机械人偶；画面不依赖影视 IP。

色彩：深海蓝 #0B1420、结构蓝 #132131、钢银 #C4CCD1、暖琥珀 #FFBD75、冷灰 #8293A5。标题采用系统 Avenir Next / 苹方，数据用等宽字体，无远程字体依赖。记忆点集中在五根能量线与具有关节的实体感机器人，其余装饰控制对比度。

使用刚性外壳挂载在真实 Bone 层级上，适合机械人偶；不是柔性皮肤 SkinnedMesh，也不声称已交付复杂商业角色资产。后续提升可在验收后替换合法正式模型，并重新测骨骼与穿模。

## 验收证据分级

1. 逻辑测试：证明坐标、滤波、状态与映射满足数学约束。
2. 合成输入集成测试：证明浏览器、真实模型推理、渲染、录制等管线工作。测试摄像头不是实景。
3. 真人验收：需要实际摄像头、用户伸手、遮挡与重新入镜、20–30 秒实拍录制。

只有第三级完成，才能说「真人实时交互完整验收通过」。模型图片测试、合成输入录像、无手稳定性跑分都不能替代。
