# 手势录制与绑定

修改前基线已保存为本地 Git 提交 `65a4f16`。该提交不包含手势录制模块；此前强化动作、分离手型规则、测试和预览均已保存。

## 使用

1. 在 Chrome 打开本地页面，点击「进入录制 / 管理样本」。正常操控与舞台取景暂停，只有录制取景工作；连接摄像头。
2. 选择要触发的动作，例如疾跑。让整只手出现在小取景窗，确认骨架能跟上手部。
3. 点击「录制我的手势」。准备 3 秒后，等待完整手掌持续可见约 0.3 秒才开始采样。默认录满 6 秒，可选 4 / 8 秒；准备与等待不占采样时间。疾跑可选择「保持手型就跑」，录制时自然保持；选择「持续摆动才跑」时则示范多个周期。无需符合原有文字规则。
4. 观察骨架回放。确认录到了想要的动作后，点击「保存并绑定」；录得不好可重录或取消。需要提前结束时，使用「结束采样并回放」；按钮在至少 1.2 秒且有 16 帧后启用，但疾跑建议录满多个周期。
5. 保存后自动选择「混合模式」，操控仍暂停。点击「返回正常操控」关闭录制取景并清空临时状态，再做一次相同动作，查看“最接近”和当前状态。每个动作最多补录至三段，建议包含略有不同的速度和位置。
6. 只需录你想自定义的动作。例如仅录疾跑时，疾跑使用样本，旋身跃起、负重、下蹲、跳跃和待机仍用原有规则，无需补录。混合模式下样本匹配成功优先触发，已绑定动作的旧规则停用；待机样本不会阻止其他动作的原规则。

识别方式还保留「原有手势规则」和「仅我的录制手势」；后者只触发已绑定动作。切换模式不会修改样本。

## 内置疾跑与录制疾跑的区别

不录制、选择「原有手势规则」时，疾跑使用拇指和小指伸开、中间三指前后摆动的定义。中指、无名指不再固定弯曲，也不再只检测食指；静止手型不跑。三指分别在估计的三维手掌坐标中计算最近 360 ms 的运动，至少两指达到门槛即可持续运行，容许第三指运动较弱或不同步。外侧手指收起或失去追踪会停止。手背朝前或朝上不设硬性朝向门槛，实际遮挡仍可能导致模型关键点不准。

以下选项只控制已经录制的疾跑，保存的样本及用户明确选择不自动改写；要使用上述内置定义，请选择「原有手势规则」。

## 已录制疾跑的触发方式

- **食指动才跑（默认）**：旧录制确认支持手型，单独检测食指相对手掌的弯曲／摆动；食指静止不跑。手型匹配不约束食指位置，允许它自由弯曲。整手平移、平面旋转和缩放被归一化，轻微抖动不应启动。
- **保持手型就跑（可选）**：保持录制的手型与朝向即可持续疾跑，不要求一直摆动；换手型或移开手停止。适合关键点中表现为稳定手型的示范。
- **持续摆动才跑**：需要保持相似手型并持续运动，停手停止。适合能稳定捕捉到摆动的示范。

切换只影响已录制疾跑，现有样本无需重录，其余动作仍使用原有规则。选择会保存在样本库，并随 JSON 导出导入；旧版保持手型默认迁移为食指运动，全部样本保留；新设置保存 `runControlVersion: 2`，之后明确选择的方式及已有整手运动设置会保留。匹配器只在当前手型符合时维持疾跑，没有把动作锁住。

宽松度默认 0.28。提高更容易匹配，也更容易误触发；优先补录有代表性的样本，不要一开始就把宽松度拉满。

## 保存与分析

只保存 21 个手部关键点、采样时间、画面宽高比、动作标签和样本时间，不保存摄像头视频、不调用外部接口。数据写入当前浏览器、当前本机地址的 localStorage；另一个浏览器或端口不会自动共享。

「导出样本给我分析」下载 JSON 文件，之后可把文件提供给 Codex，直接分析实际轨迹，不必只用语言描述。「导入并替换样本」会替换当前浏览器内的样本集合。浏览器清理数据也会影响保存，因此建议导出备份。

移除按钮只在你主动点击时移除对应样本；移除最后一段后自动切回原有规则，避免空样本的个人模式阻断动作。录制取消不会影响已保存样本。刷新后保留样本：有样本时默认混合模式，无样本时默认原有规则。兼容旧版样本，原有数据不会自动清除。旧样本太短或录错时，建议重新录一段 6 秒示范，并勾选「保存时替换这个动作的旧样本」；保存失败或取消会保留旧绑定，其他动作不受影响。

## 实现与边界

此版本是本地示例轨迹匹配，不是训练新的神经网络。MediaPipe 继续负责提取手部关键点。录制轨迹经过手掌尺度和位置归一化，保留朝向、手指相对位置、腕部平移与距离变化；非疾跑动作的短时间窗口通过动态时间规整（DTW）比较，结合运动幅度判断。动态疾跑比较手型均值、关节与腕部运动幅度，不要求重复摆动从同一个阶段开始。每份录制除整段特征外，还保留最多 9 个约 1.25 秒的局部片段特征，让实时短窗口能匹配录制中实际出现过的不同角度和幅度，避免只有整段平均值可用；既包含三指弯曲，也包含整手位移。最近 400 ms 的运动与手型用于退出判断：在仍有运动且手型相近时允许最多约 450 ms 的短暂失配，停手、换手型或丢手会退出。它不是锁定疾跑，仍需持续手势输入。不同状态过于接近时拒绝触发；录制质量不足或间断超过 250 ms 时拒绝保存；在「持续摆动才跑」下，新录制疾跑几乎没有运动也会拒绝保存。「保持手型就跑」接受稳定手型。均值和幅度不能区分所有不同运动顺序，仍需要真人试用。

识别需要观察一小段轨迹，不能承诺零延迟。速度、遮挡、掌心侧向、左右手或手离镜头距离变化很大时，可能需要补录样本。若小取景窗中的骨架本身识别错了，应先调整拍摄角度或光线，录制绑定无法弥补错误的关键点输入。

从进入录制到返回操控的整个过程，正常规则与个人样本匹配暂停，主舞台取景与渲染暂停。只有录制取景使用同一摄像头和同一 MediaPipe Worker，没有第二次模型推理；未点击录制时只预览，不保存帧。返回时清空临时状态、取消未保存的本次录制，保存的样本保留。正常操控时只运行选定的识别方式，不更新录制取景或录制采样。关闭摄像头或切换输入会取消未完成的录制；模拟操控不能作为录制输入。

## 录制按钮变灰时（2026-09-15 更新）

摄像头与追踪模型就绪后，「录制我的手势」即可点击，不再要求点击瞬间手必须在镜头里。选择动作、点击录制后，有 3 秒准备时间，之后会继续等待手部就绪，再开始默认 6 秒完整采样。等待手部超过 10 秒会提示重试。没有捕捉到完整序列时会提示重录，不能保存空样本。

摄像头未连接、正在加载或已在准备／等待手掌／录制时，录制按钮仍会禁用。预览下方会显示连接与手部检测状态。「保存并绑定」只在录制成功、出现骨架回放后启用。切换到后台会关闭摄像头，返回后需重新连接。

## 重新打开后样本还在，但动作不触发

先查看样本列表中的录制时间、时长和帧数，确认看到的是刚才保存的那一段。Chrome 与 Codex 内置浏览器的样本独立，`localhost` 与 `127.0.0.1`、不同端口的样本也独立；列表里有“疾跑”不代表加载的是同一段录制。

点击「检查已存样本」会在本地用已保存的关键点和新建匹配器重放检测，不启动摄像头、不改写绑定。“自检可触发”说明这份样本在重新初始化后仍能触发自己，不能证明真实手势准确率。食指运动模式显示“回放中疾跑占比”：录制里静止的部分应当不跑，低占比不代表手型模板无效。请通过实时动／停食指验证。其他模式的百分比也不是神经网络置信度。

返回正常操控、连接摄像头并连续做动作时，面板会显示匹配原因：缺少连续手部输入、手型或朝向差异、运动不足、轨迹差异或正在确认。优先根据原因检查，不必先删除样本或调高宽松度。新回归测试覆盖 JSON 恢复、新页面时间起点和重新连接后的疾跑识别。

长录制的分段特征在加载时从旧数据直接计算，不改写样本，也无需重录。对于换手型，除整体手型距离外还约束单个代表关节的差异，减少拇指或小指收起后仍被其他相似关节掩盖的情况。

食指检测观察最近约 280 ms 的第 6、7、8 号关节相对手掌的运动，使用不同启停门槛减少临界抖动，停指不额外延长保持。合成测试覆盖不同帧率下停指 400 ms 内退出；真人端到端延迟仍受摄像头和推理影响。若原始关键点没有体现食指运动，匹配层无法凭空恢复，页面会提示等待食指运动。
