# 第二版：手势意图与全身动作

日期：2026-09-13。基线：本地提交 `43ff96d`。继续采用 Three.js + 本地 MediaPipe，不需要 TouchDesigner。

## 已实现

输入层用掌长归一化指间距离、指节伸展、手腕速度和手掌旋转速度。规则识别独立于动作层；骨骼不再由五个指尖分别抢占控制。五路提线继续跟随真实骨骼端点。

| 动作 | 真人手势 | 执行与退出 |
| --- | --- | --- |
| 待机 | 放松张掌，无明确意图 | 轻微呼吸、头部活动 |
| 跑动 | 食指、中指朝下伸直，收起其余手指并前后摆动 | 双腿交替抬脚、双臂反向摆动；停止运动后收势 |
| 转身 | 只伸出食指，收起其余手指，像转钥匙一样转动手腕 | 根据转动方向整体旋转，脚步交替；停转后保留朝向，重置可回正 |
| 负重 | 拇指食指捏合并保持 | 双臂举落与身体起伏协调；松开卸力 |
| 下蹲 | 握拳向下压 | 髋膝屈曲，脚底接地；保持拳头维持下蹲 |
| 跳跃 | 下蹲后快速上提并张手 | 约 1.35 秒的蓄力、起跳、腾空、落地缓冲；动作完成前不中断，不因持续手势连跳 |

疾跑与旋身使用互斥手型；旋身只接受单独伸出的食指，疾跑只接受朝下的食指和中指。换手型会清空运动缓存。捏合使用进入/退出两套距离阈值，普通动作需约 65–80 ms 稳定确认。退出意图有 150 ms 稳定判定；跑动/旋转短暂保持约 230/260 ms，避免采样间隙闪跳。以上是控制参数，不是端到端延迟实测。

追踪丢失 250 ms 后清除手势状态，角色过渡到待机；已经起跳会先完成落地。重新连接、镜像切换及关闭输入会重置动作控制。手势识别不必等待位置校准，校准仅影响少量位置/头部修饰。

## 动作实现

- `src/actions.js`：特征提取、GestureInterpreter、ActionDirector、程序化全身动作和双骨骼腿部 IK。
- `src/robot.js`：新增独立脚踝骨骼，髋膝踝联动，脚底保持水平；紫色装甲和肩部/大腿细节。
- 跑动相位按时间积分，改变速度不会重置步态。动作切换用 160 ms 过渡，跳跃使用自己的轨迹。
- `src/core.js`：校准姿态与当前手掌方向对齐，避免整只手旋转误驱动多个手指通道。
- 点平滑由 45 ms 调整为 22 ms；位置修饰平滑由 100 ms 调整为 45 ms。主动作不再穿过旧关节双重平滑。
- 真人模式使用全幅摄像头合成；模拟模式保留可读的手部取景框。提线增加细丝层，动作状态清楚显示。

这是自制刚性骨骼角色与程序化动作，未导入原视频作者的 FBX，也不是完整物理引擎或环境接触求解。脚部约束相对于本项目的虚拟舞台，摄像头背景未做真实地面空间定位。减少动态效果偏好会关闭提线流动粒子；用户主动触发的动作仍会播放。

## 试用

打开页面，点击动作库可直接试播；键盘 1–6 分别对应六种动作。试播会切换到模拟输入并关闭摄像头，画面明确标记 SIMULATION。点击「返回摄像头手势控制」开启真人控制。重置会恢复默认增益、清空覆盖并回正角色。

## 验证

- `npm test`：核心与动作测试，覆盖手掌尺度/旋转、捏合抖动与松开、滑动和旋转冲突、下蹲起跳、丢手、动画过渡以及脚踝位置/水平约束。
- `tests/actions_browser_test.py`：六种动作、单次跳跃回待机、键盘、录制、实际本地模型 + 模拟摄像头、关闭视频轨道及 390 px 布局。
- `tests/gestures_browser_test.py`：合成 21 点经 Worker 接口回放到页面，验证五种动作意图、完整起跳落地及丢手恢复。此测试替换了模型输出，不评价 MediaPipe 真人识别准确率。
- 动作预览：`recordings/actions-v2-SIMULATION.mp4`，明确为按钮试播录制，不是真人识别录像。

新版截图和结果存于 `docs/evidence/v2/`。旧版 10 分钟测试与真实摄像头记录仅属于旧基线，不据此宣称新版已经完成同等真人验收。

帧处理指标只测量取帧派发到结果返回。手势确认指标记录最近一次状态切换前的候选稳定时间。两者均不包含完整的摄像头曝光与显示扫描。
