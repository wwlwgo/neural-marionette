# 故障排查

## 显示「没有找到摄像头」

本次 Codex 内置浏览器实际返回过此错误。先使用 Google Chrome 打开 http://127.0.0.1:5173 。连接 USB 摄像头或可用的连续互通相机；在 Chrome 设置 → 隐私和安全 → 网站设置 → 摄像头检查是否列出设备，然后回到页面点击连接。

如果没有设备，可用「模拟操控」检查视觉与机械控制。该模式不会假装启用了摄像头。

## 摄像头权限未开启

点击 Chrome 地址栏的网站设置图标 → 摄像头 → 允许。还需检查 macOS 系统设置 → 隐私与安全性 → 摄像头 → Google Chrome。返回应用重新连接。

## 摄像头被占用/断开

关闭占用摄像头的视频会议应用，检查连接线，回到页面重新连接。程序会释放 Worker 和视频轨道；不会保留无限静止的最后一帧作为控制。

## 模型加载失败

在项目目录运行 npm run assets；检查 public/models/hand_landmarker.task、public/vendor/vision_bundle.js 与 public/wasm 是否存在。模型正常大小为 7,819,105 字节，SHA256 见 assets/licenses/model-manifest.json。不要把不同版本 MediaPipe 的 WASM 混在一起。

首次下载失败可以恢复网络后重新运行；不要从不明网站下载模型替代。

## 机器人不跟手/一直校准

确保状态是 LIVE CAMERA，手掌完整入镜且光线充足。把手掌保持稳定约半秒。点击重新校准。模拟操控下只有鼠标、自动微动或调试滑块生效。

## 机器人抖动或动作太大

降低牵引强度，给手部更均匀的正面光，避免手与背景同色。适当增加 motion.landmark_tau_ms 或 joint_tau_ms 会更稳，但会增加延迟；仍需重新测真人响应。

## 画面卡顿

选择轻量 720p；关闭其他重型 3D 程序。在 Chrome 设置 → 系统确认硬件图形加速正常。渲染 FPS、推理耗时和追踪 Hz 是不同指标，先导出诊断再定位。

## 启动提示端口占用

使用 .command 启动器会复用已启动项目或尝试 5173–5189。手动命令可指定其他端口，例如 npm run dev -- --port 5174 --strictPort。不要停止不相关程序来释放端口。

## 浏览器切到后台后摄像头关闭

这是预期行为。回到页面点击连接即可恢复，防止后台继续拍摄或积压输入。

## 开始录像后卡顿

内置录像会自动开启「录屏优化」（720p / 30 帧）。系统区域录屏需要先手动勾选该开关；网页无法自动检测系统录屏。避免同时启动内置与系统两份录像。若仍卡顿，保持开关开启并导出诊断，比较录屏前后的渲染 FPS、追踪 Hz 和帧处理耗时。内置浏览器与独立 Chrome 的图形路径可能不同；换浏览器前导出个人手势样本备份。步骤与测试边界见 [录屏说明](RECORDING.md)。

## 录像不能下载

优先使用 Chrome。录制时输出尺寸被锁定，停止后才可切换画质；文件名的 SIMULATION 表示模拟来源。若系统不支持任何 MediaRecorder 编码器，会显示可读错误，不产生虚假录像。

## Python 无法启动

应用运行不需要 Python。本机 Homebrew Python 的 expat 动态库异常是已有环境问题，没有改动系统库。核心启动只需 Node；测试可使用已准备的系统 Python 依赖。
